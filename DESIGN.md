# Beszel Design

The tray, screen notch (Plus), and desktop widgets summarize fleet health using a monochrome Tabler Icons mark (`tabler:server`). State and surface trees are driven by a Vue 3.5 reactive store (`ref` / `shallowRef` / `computed` / `watch` / `effectScope`) that builds native VNodes with Vue `h()` and invalidates only when active outputs change.

The flyout panel stays at a fixed `460 × 540` footprint across every view (setup, cards, table, detail, alerts) to prevent height jitter and spurious scrolling on short lists. A single-row top header pairs with a 3-card compact KPI strip, native `MenuButton` sorting in card mode, contextual search when managing > 6 servers, cards/table toggle (persisted locally), and a streamlined Alerts view aggregating deduplicated active anomalies and optional Metrix.Bar Plus Inbox webhook/email messages. Wide windows (≥ 840 DIP) automatically split into a side-by-side server list and live detail pane. Colors align with Beszel's palette (`--chart-1`..`--chart-5` and 65% / 90% green/yellow/red meters).

Opening a server immediately serves cached `(systemId, period)` snapshots when fresh, streams `system_stats` first so charts paint ahead of secondary collections, aborts superseded requests across host/period switches, and drains error response bodies to stay within the host's 4-concurrent-fetch budget. Detail views include switchable 1h / 12h / 24h / 7d CPU, memory, network (`stats.b` with legacy `ns`/`nr` fallback), and disk I/O charts, hardware details (`system_details` with `systems.info` fallback), containers with memory and health indicators, systemd services, and S.M.A.R.T. disks.

Scheduled refreshes await only the core `systems` and `alerts` queries so the host's single-call scheduler remains responsive to UI clicks. Plus Inbox syncs re-probe capabilities dynamically, pre-warm recent message bodies sequentially into the host SQLite cache, parse both plain-text and JSON Shoutrrr webhooks cleanly, and guard deletions against concurrency (`inbox busy`) and stale list overwrites.

The codebase follows a four-layer modular architecture: `src/host/` isolates all optional `$metrix` / `localStorage` / `Notification` boundaries, `src/beszel/`, `src/inbox/`, and `src/domain/` own explicit state machines (single-flight auth session, detail cache/abort loader, inbox sync/prewarm/delete service, alert transition cooldowns), `src/store.ts` drives reactive state and an explicit `PanelScreen` union, and `src/ui/` splits pure VNode rendering across `panel/*` and `surfaces/*` while reusing `es-toolkit`, `pretty-bytes`, `ufo`, and `destr`.
